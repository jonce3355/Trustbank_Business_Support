# Trustbank Support — служба поддержки банка в Telegram

Эта инструкция написана для человека без опыта программирования.
Выполняйте шаги строго по порядку — ничего не пропускайте.

Если на каком-то шаге появится ошибка — не пытайтесь чинить её
самостоятельно. Просто скопируйте текст ошибки (и сделайте скриншот)
и пришлите — вместе разберёмся. Подробнее — в разделе
["Если что-то не работает"](#если-что-то-не-работает) в конце файла.

---

## Что это за система

Клиенты банка пишут в один Telegram-бот, их сообщения превращаются в
"обращения" (тикеты), которые видят и обрабатывают сотрудники нужного
филиала — в отдельном мини-приложении внутри второго Telegram-бота.
Есть отдельная роль Супер-администратора, которому видно всё: все
филиалы, всех сотрудников, все обращения и статистику (SLA).

```
Клиент → Customer Bot → Backend → Ticket (привязан к филиалу)
                                       ↓
                          Employee Web App (внутри Employee Bot)
                                       ↓
Клиент ← Customer Bot ← Backend ← Ответ сотрудника
```

## ШАГ 1. Установите Node.js

Node.js — программа, которая нужна, чтобы один раз локально запустить
пару вспомогательных команд (создание первого пароля филиала и
подключение вебхуков). Сам бот на вашем компьютере работать не будет —
он будет жить на Vercel.

1. Откройте https://nodejs.org
2. Скачайте версию **LTS** (кнопка слева, с подписью "Recommended for
   most users")
3. Установите как обычную программу (Далее → Далее → Установить)
4. Проверьте установку: откройте терминал —
   - **Windows**: нажмите Win, наберите `cmd`, откройте "Командная строка"
   - **Mac**: откройте приложение "Терминал" (Terminal)
   и введите:
   ```
   node -v
   ```
   Если видите номер версии (например `v20.11.0`) — всё установилось.

## ШАГ 4. Создайте двух ботов через @BotFather

1. Откройте Telegram, найдите бота **@BotFather**, нажмите **Start**

### Клиентский бот

2. Отправьте команду:
   ```
   /newbot
   ```
3. BotFather спросит имя — введите, например: `Trustbank Support`
4. Затем спросит username — он должен заканчиваться на `bot`, например:
   `trustbank_support_bot`
5. BotFather пришлёт сообщение с токеном — строка вида
   `123456789:AAExampleTokenDoNotShareXXXXXXXXXXX`
   **Скопируйте её** — это ваш `CUSTOMER_BOT_TOKEN`. Никому его не показывайте.
6. (Необязательно, для красоты) настройте бота:
   - `/setdescription` — выберите бота → введите описание, например
     "Служба поддержки Trustbank для клиентов"
   - `/setuserpic` — загрузите логотип банка

### Бот для сотрудников

7. Снова отправьте `/newbot`
8. Имя, например: `Trustbank Employee Support`
9. Username, например: `trustbank_employee_bot`
10. Скопируйте токен — это `EMPLOYEE_BOT_TOKEN`
11. Так же можно задать описание через `/setdescription`

В итоге у вас должно быть два токена — сохраните их пока в любом
текстовом файле на компьютере (не отправляйте их мне, они понадобятся
только для настройки .env и Vercel).

## ШАГ 6. Создайте базу данных в Supabase

1. Откройте https://supabase.com, нажмите **Start your project**,
   зарегистрируйтесь (проще всего — через GitHub)
2. Нажмите **New Project**
3. Укажите:
   - Name: `trustbank-support`
   - Database Password: придумайте надёжный пароль и **сохраните его**
     (он редко понадобится напрямую, но лучше сохранить)
   - Region: выберите ближайший к себе
4. Нажмите **Create new project** и подождите 1–2 минуты, пока
   Supabase создаст базу

### Получите строку подключения (DATABASE_URL)

5. В меню слева откройте **Project Settings** (значок шестерёнки) →
   **Database**
6. Найдите раздел **Connection string** → вкладка **Transaction** (или
   "Transaction pooler") — именно она нужна, а не "Session"/"Direct
   connection" (у нас сервер serverless, ему нужен режим с пулингом)
7. Скопируйте строку вида:
   ```
   postgresql://postgres.xxxxxxxx:[YOUR-PASSWORD]@aws-0-xxxxx.pooler.supabase.com:6543/postgres
   ```
8. Замените `[YOUR-PASSWORD]` на пароль базы данных, который вы
   задавали на шаге 3 (без квадратных скобок). Это и есть ваш
   `DATABASE_URL`.

### Создайте таблицы

9. В меню слева откройте **SQL Editor**
10. Нажмите **New query**
11. Откройте файл `schema.sql` из папки проекта (можно обычным
    блокнотом), скопируйте **всё содержимое**
12. Вставьте в SQL Editor и нажмите **Run** (или Ctrl/Cmd + Enter)
13. Должно появиться "Success. No rows returned" — значит все таблицы
    и филиалы созданы

Проверить: слева откройте **Table Editor** — там должны появиться
таблицы `branches`, `employees`, `tickets` и другие, а в `branches`
— уже 14 строк с вашими филиалами.

## ШАГ 7. Заполните файл .env на компьютере

1. В папке проекта найдите файл `.env.example`
2. Сделайте его копию и переименуйте копию в `.env` (именно так,
   с точкой в начале, без `.example`)
3. Откройте `.env` в блокноте и заполните:

```
NODE_ENV=production
PORT=3000

DATABASE_URL=вставьте строку из Шага 6

CUSTOMER_BOT_TOKEN=вставьте токен клиентского бота из Шага 4
EMPLOYEE_BOT_TOKEN=вставьте токен бота сотрудников из Шага 4

WEB_APP_URL=

SUPER_ADMIN_TELEGRAM_ID=вставьте число из Шага 5

FIRST_RESPONSE_SLA_MINUTES=15
RESOLUTION_SLA_MINUTES=240
```

Поле `WEB_APP_URL` пока оставьте пустым — заполним его после деплоя
на Vercel (шаг 9).

## ШАГ 8. Создайте первый пароль филиала

Без этого шага никто (даже вы) не сможет зарегистрироваться в
Employee-боте — пароль филиала обязателен при регистрации сотрудника.

1. В терминале, находясь в папке проекта, придумайте пароль (например
   для головного офиса `00491`) и выполните:
   ```
   npm run set-password -- 00491 ВашНадежныйПароль123
   ```
   (замените `ВашНадежныйПароль123` на свой пароль — **запомните
   его**, он понадобится при регистрации в Employee-боте)
2. Должно появиться:
   ```
   Готово! Пароль создан для филиала 00491 — OPERU (Головной офис).
   ```

При желании создайте пароли и для других филиалов — команда та же,
просто с другим кодом:
```
npm run set-password -- 11966 ДругойПароль456
```
(Позже дополнительные пароли можно будет создавать и через Web App,
уже не через терминал — см. раздел "Как создать пароль филиала после
установки".)

## ШАГ 9. Разместите проект на Vercel

Vercel — сервис, который бесплатно и постоянно держит ваш сайт/бота
включённым, с готовым HTTPS-адресом.

### 9.1. Загрузите код на GitHub (если ещё не сделано)

Код уже находится в репозитории `jonce3355/trustbank_business_support`,
ветка `claude/telegram-bank-support-system-q41n3m` — этот шаг уже
выполнен.

### 9.2. Подключите Vercel

1. Откройте https://vercel.com, нажмите **Sign Up**, выберите
   **Continue with GitHub** и разрешите доступ
2. Нажмите **Add New...** → **Project**
3. Найдите репозиторий `trustbank_business_support`, нажмите **Import**
4. В настройках убедитесь, что выбрана ветка
   `claude/telegram-bank-support-system-q41n3m` (если Vercel сразу
   предлагает другую ветку — после первого деплоя в разделе Settings →
   Git можно указать нужную)

### 9.3. Добавьте переменные окружения

Перед нажатием Deploy разверните раздел **Environment Variables** и
добавьте по одной (имя — значение), взяв значения из вашего файла
`.env`:

| Имя | Значение |
|---|---|
| `DATABASE_URL` | строка из Supabase |
| `CUSTOMER_BOT_TOKEN` | токен клиентского бота |
| `EMPLOYEE_BOT_TOKEN` | токен бота сотрудников |
| `SUPER_ADMIN_TELEGRAM_ID` | ваш Telegram ID |
| `FIRST_RESPONSE_SLA_MINUTES` | `15` |
| `RESOLUTION_SLA_MINUTES` | `240` |

`WEB_APP_URL` пока не добавляйте — мы не знаем адрес, пока не
задеплоим первый раз.

5. Нажмите **Deploy** и подождите 1–2 минуты
6. После завершения Vercel покажет ваш адрес, что-то вроде:
   ```
   https://trustbank-business-support.vercel.app
   ```
   Скопируйте этот адрес.

### 9.4. Добавьте WEB_APP_URL и передеплойте

7. В проекте на Vercel откройте **Settings** → **Environment Variables**
8. Добавьте `WEB_APP_URL` = адрес из предыдущего пункта (без слэша в
   конце)
9. Откройте вкладку **Deployments**, у последнего деплоя нажмите на
   `...` → **Redeploy**, чтобы новая переменная применилась

### 9.5. Обновите локальный .env и подключите вебхуки

10. Откройте свой локальный файл `.env` (на компьютере) и впишите туда
    тот же `WEB_APP_URL`
11. В терминале выполните:
    ```
    npm run set-webhooks
    ```
12. Должны появиться две строки:
    ```
    ✅ Customer Bot: webhook установлен -> https://.../webhook/customer
    ✅ Employee Bot: webhook установлен -> https://.../webhook/employee
    ```

## Тестирование

Пройдите все пункты по порядку.

**Тест 1.** В клиентском боте нажмите /start → выберите филиал (например
`00491`) → выберите категорию → напишите "Платёж не отправляется".
Ожидаемо: бот подтвердит номер обращения (например #10001).

**Тест 2.** В Employee Web App откройте это обращение → "Взять в
работу" → напишите "Добрый день" → "Отправить". Ожидаемо: клиент в
Telegram получает это сообщение от Customer-бота.

**Тест 3.** Клиент отвечает "Спасибо". Ожидаемо: сообщение появляется в
переписке у сотрудника в Web App.

**Тест 4.** Зарегистрируйте второго сотрудника с паролем другого
филиала (`npm run set-password -- 11966 Пароль2`, затем регистрация в
боте). Ожидаемо: этот сотрудник НЕ видит обращение #10001 из филиала
00491.

**Тест 5.** Супер-администратор видит обращение #10001 в списке (без
ограничения по филиалу).

**Тест 6.** Супер-администратор → вкладка "Админ" → "Сотрудники" —
видит сотрудника филиала 00491 со статистикой.

**Тест 7.** Супер-администратор → вкладка "Админ" → "SLA" — видит время
первого ответа и решения по филиалам и категориям.

**Тест 8.** В Web App откройте обращение → "Решено" → затем "Закрыть".
Ожидаемо: в SLA-статистике по этому обращению появляется время решения.

**Тест 9.** После закрытия обращения клиент пишет новый вопрос — бот
снова спросит категорию и создаст новый номер обращения (например
#10002).

**Тест 10.** Супер-администратор блокирует сотрудника (Админ →
Сотрудники → Заблокировать). Ожидаемо: при следующем /start в
Employee-боте этот сотрудник видит "Ваш доступ заблокирован", а Web App
для него отвечает ошибкой доступа.

## Как создать пароль филиала после установки

Больше не нужен терминал — как Супер-администратор:

1. Откройте Web App → вкладка **Админ** → **Филиалы**
2. Рядом с нужным филиалом нажмите **Создать пароль**
3. Введите новый пароль в появившемся окне — готово

Там же можно создать новый филиал (внизу вкладки "Филиалы").

## Как заблокировать/разблокировать сотрудника или изменить его филиал

Web App → **Админ** → **Сотрудники** → кнопка рядом с сотрудником.
(Изменение филиала сотрудника пока делается через прямой запрос к API
`POST /api/admin/employees/:id/branch` — если понадобится, отдельно
попросите добавить для этого кнопку в интерфейс.)

## Как обновить код в будущем

Если вы получите от AI обновлённые файлы:

1. Замените соответствующие файлы в папке проекта на новые
2. Если менялся `package.json` — выполните `npm install`
3. Если код лежит в GitHub-репозитории — просто отправьте
   (запушьте) изменения в ветку `claude/telegram-bank-support-system-q41n3m`

5. Если менялась схема базы (`schema.sql`) — откройте Supabase SQL

## Если что-то не работает

Не пытайтесь разобраться самостоятельно. Пришлите три вещи:

1. **Текст ошибки** — скопируйте его полностью
2. **Скриншот** экрана, где это произошло
3. **Логи** — на Vercel: откройте проект → вкладка **Logs** (или
   **Deployments** → выберите последний деплой → **Functions** →
   посмотрите вывод) — скопируйте последние строки

### Частые причины ошибок в /health

- `database: error` → неверный `DATABASE_URL` в Vercel Environment
  Variables (проверьте, что использована строка "Transaction pooler",
  а не "Direct connection", и что пароль в строке верен)
- `customerBot: error` или `employeeBot: error` → неверный токен, либо
  токен не сохранён в Vercel Environment Variables
- `branches: no branches configured` → не выполнен `schema.sql` в
  Supabase SQL Editor

### Бот не отвечает в Telegram

- Проверьте, что вы выполнили `npm run set-webhooks` **после** того,
  как в `.env` появился финальный `WEB_APP_URL`
- Убедитесь, что `WEB_APP_URL` в Vercel и в локальном `.env` совпадают
  и не содержат опечаток

## Что не реализовано в этой версии (сознательно, для простоты MVP)

- Вложения (фото, PDF) — структура базы (`messages.attachment_type`,
  `attachment_id`) уже позволяет добавить это позже без переделки
- Push-уведомления о приближающемся нарушении SLA (за 5 минут до
  просрочки) — пока SLA виден только в разделе "Админ → SLA"
- Смена филиала сотрудника через кнопку в интерфейсе (доступно через
  прямой вызов API, см. выше)

Всё остальное из технического задания реализовано и работает.
